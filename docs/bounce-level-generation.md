# Bounce 레벨 생성 규칙

2026-10-27. 출시 140개 중 이번 재제작 범위는 1~20이다.

## 1. 레벨의 질문

모든 레벨에 **“어디를 먼저 공략해야 다음 공격이 유리해지는가?”**의 구체적인 답을 적는다. 일반 레벨은 핵심 판단 하나, 도전 레벨은 배운 판단 두 개를 연결한다. 정답은 하나일 필요가 없다. 올바른 관찰에 여러 유효한 조준 방향이 있어야 한다.

먼저 문제, 유리한 진입로, 다음 공격에서 얻는 이득을 설계한다. 그다음 고래·사과·하트 등 읽히는 사물 형태와 색상을 입힌다. 무작위로 기믹을 추가하거나 블록 수만 늘리는 방식으로 난이도를 만들지 않는다. 색상은 시각 구분이며 일반 블록의 체력은 모두 1이다.

## 2. 고정 조건

- 출시 외곽 Wall은 11×16, 셀은 1유닛, 카메라 기준 Size 11.75 / pitch 60°. 내부 Grid만 바꾸며 넓은 레벨을 자동 축소하지 않는다.
- 1~13은 일반 블록만 사용한다. 기뢰 14, 금속관 21, 찬장 41, 이동 패널 61, 스위치·문 81, 방향 장갑 101, 연속 타격 121에 처음 도입한다.
- 도입과 다음 두 레벨은 새 규칙 단독 학습이다. 이후 이미 배운 기믹의 재등장·혼합을 허용한다.
- 큰 사물 윤곽, 충분한 블록 밀도, 알아볼 수 있는 색 배치를 유지한다. 빈 통로도 문제의 일부이며, 블록 수를 맞추려고 통로를 메우지 않는다.
- 요청 범위 밖 레벨의 배치·기믹·공 예산을 보존한다. 140 이후는 반복시키지 않는다.

## 3. 난이도와 순서

1~3은 조준·반사 조작을 익히는 예외 구간이다. 이후 진입 방향 선택, 안쪽 공간 진입, 입구를 먼저 여는 순서를 점진적으로 가르친다. 작은 틈의 정밀 조준만으로 어렵게 만들지 않는다. 휴식 레벨은 판단 수를 줄이고, 도전 레벨은 이미 익힌 판단을 연결한다.

## 4. 설계 기록

레벨마다 핵심 질문, 권장 첫 공략, 그 선택의 다음 공격 이득, 쉬운 우회 가능성, 실수 후 복구 방법을 기록한다. 의도와 측정 결과를 구분한다. `intent`는 카탈로그에서 읽을 수 있는 구체적 한 문장으로 남긴다.

## 5. 기믹의 인과관계

| 기믹 | 배치 목적 | 실패하는 배치 |
| --- | --- | --- |
| 기뢰 | 폭발로 입구나 막힌 면을 열어 이후 공이 안쪽으로 들어간다 | 외딴 기뢰를 쏘기만 하면 끝나거나 아무 때나 터뜨려도 동일 |
| 금속관 | 제거에 공을 투자하면 가치 있는 진입로가 열린다 | 우회가 항상 더 싸고 관이 주요 경로와 무관 |
| 찬장 | 인접 블록에 여러 번 닿는 방향을 선택한다 | 가장 가까운 블록을 쏘는 것과 차이가 없음 |
| 스위치·문 | 문이 유용한 경로를 실제로 막고 스위치가 접근성을 바꾼다 | 문을 무시해도 같은 경로로 해결 |
| 방향 장갑 | 배운 반사로 약점 면에 접근한다 | 도입 외에도 정면 직사가 항상 정답 |
| 연속 타격 | 한 공의 복귀 경로를 만든다 | 연속 타격 여부가 운에만 달림 |
| 이동 패널 | 읽을 수 있는 타이밍 구간을 선택한다 | 한 프레임 단위 입력만 성공 |

혼합은 역할이 연결될 때 사용한다. 예: 기뢰로 진입로 개방 → 반사로 약점 공략. 종류 수 자체를 난이도 점수로 쓰지 않는다.

## 6. 공 예산

배치가 먼저이고 공 예산은 검증 후 정한다. 블록 수에 비례하는 넉넉한 기본값은 탐색용일 뿐 출시 예산이 아니다. 측정된 유리한 경로에 조작 오차와 최소 2~3회 실수 여유를 더한다. 초기 조작 학습은 더 넉넉하게 둔다. 쉬운 배치를 공 부족으로만 어렵게 만들지 않는다.

## 7. 검증과 합격 판단

1. 실제 런타임 물리로 공을 발사하여 예산 안에 클리어하고 동일 입력을 재생한다. 직접 파괴·부스터·추가 공을 사용하지 않는다.
2. 가까운 대상의 중앙을 우선하는 단순 정책과 경로를 고려하는 정책을 같은 조건에서 비교한다. 정책 이름·사용 공·실패 여부·적용 소스 해시를 남긴다.
3. 기믹 작동 전후 접근성과 공략 순서의 이득을 확인한다. 자동 정책의 성공만으로 설계 의도가 입증됐다고 하지 않는다.
4. 쉬운 우회가 의도한 경로와 비슷한 비용이면 배치를 재설계한다. 유효한 대안 풀이 자체를 막지는 않는다.
5. 대표 유리한 각도의 주변 입력도 검사한다. 초반 20개는 매 발사에 +1°/-1° 오차를 번갈아 넣고 현재 배치에서 다시 조준하는 경로를 추가 측정한다. 이 경로의 사용 공 +3발도 예산 하한에 포함한다. 이는 모든 각도 오차를 보장하는 검사가 아니다. 이동 패널은 타이밍 폭을 별도로 확인한다.
6. 첫 공 실수 뒤에도 회복할 여유와 경로가 있는지 확인한다.

일반 레벨은 단순 정책이 유리한 경로보다 공을 약 25% 이상, 도전은 약 40% 이상 쓰는 것을 **초기 튜닝 목표**로 삼는다. 절대 합격 공식이나 사람의 승률이 아니다. 조작 도입·휴식은 예외 사유를 기록한다. 목표 미달은 공개하고 수동 플레이로 판단할 항목을 남긴다. 자동 클리어, 전략적 차이, 사람의 체감 난이도는 각각 별도 검증이다.

## 제작 경로

- `tools/balance/build_release_levels.py`: 캠페인 조립. 초반 설계는 `build_opening_levels.py`가 담당한다.
- `tools/balance/release-budgets.json`: 배치 해시가 일치할 때만 적용하는 예산.
- `python tools/balance/build_release_levels.py`: 데이터 생성.
- Unity EditMode 전체 → PlayMode 탐색/비교 → 요청 범위 예산 보정 → EditMode → 최종 PlayMode 순서로 검증한다.
- `BounceReleaseFlowTests`: 140개 클리어·재생, 14레벨 정상 속도 물리, 튜토리얼/캠페인 끝 검증.
- `python tools/balance/build_level_catalog.py --accept-run`: `TestResults/release-final.xml`과 일치하는 최종 증거만 카탈로그에 반영한다. 실패·오래된 증거를 성공으로 표시하지 않는다.
- 한글 커밋과 해당 원격 브랜치 푸시까지 완료한다. 사용자 기존 변경을 포함하지 않는다.

## make-level 스킬

저장소 원본은 `tools/skills/make-level/SKILL.md`이며 사용자 Codex skills 폴더에 같은 내용을 설치한다. 스킬 선택 또는 `$make-level`로 호출한다. 프로젝트의 `AGENTS.md`에도 `/make-level` 요청을 이 절차로 해석하도록 등록했다. 이는 별도의 네이티브 슬래시 명령 등록을 뜻하지 않는다. 예: `/make-level 1~20을 위 규칙으로 재설계해줘`. 현재 세션의 스킬 목록에 새 설치가 나타나지 않으면 새 세션에서 사용한다.
