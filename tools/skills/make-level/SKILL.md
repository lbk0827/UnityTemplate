# Make Level

프로젝트 루트의 `AGENTS.md`, `CLAUDE.md`, `docs/bounce-level-generation.md`를 읽는다. 이 스킬은 UnityTemplate Bounce용이며 루트가 다르면 파일을 찾아 프로젝트를 확인한다. 고정 설치 경로를 가정하지 않는다.

사용자가 지정한 레벨 범위와 승인된 방향으로 제작한다. 지정하지 않은 범위까지 재생성하거나 예산을 바꾸지 않는다. Bounce 변경은 `develop-bounce`에서 관리하고 사용자 변경을 보존한다.

각 레벨에 “어디를 먼저 공략해야 다음 공격이 유리해지는가?”의 구체적 답을 먼저 적는다. 질문 → 진입로/공략 순서 → 사물 윤곽과 색 → 기믹 역할 → 실제 물리 검증 → 공 예산 순으로 작업한다. 일반은 판단 하나, 도전은 두 판단 연결. 기믹 개수와 공 부족만으로 난이도를 만들지 않는다.

11×16 고정 외곽, 1유닛 셀, 카메라 11.75를 지킨다. 신규 기믹은 14/21/41/61/81/101/121, 도입 후 두 레벨은 단독 연습이다. 이미 배운 기믹은 이후 혼합할 수 있다. 세부 역할과 검증 기준은 규칙 문서를 따른다.

원본은 `tools/balance/build_release_levels.py`와 초반용 `build_opening_levels.py`다. 생성 JSON만 수정하지 않는다. 요청 밖 레벨을 생성 전후 구조적으로 비교한다. 공 예산은 `release-budgets.json`의 배치 해시와 함께 변경한다. 전체 예산 보정 스크립트를 부분 작업에 무조건 실행하지 않는다.

실제 런타임 발사로 클리어·동일 입력 재생을 검증하고, 단순 조준과 경로 선택의 사용 공 차이, 우회, 각도 허용 폭, 실수 복구를 확인한다. 측정하지 않은 전략 이득을 사실로 기록하지 않는다. 자동 통과를 사람의 승률이나 최적해로 설명하지 않는다. 목표 미달은 숨기지 않고 수정하거나 검토 항목으로 남긴다.

Unity 버전은 `ProjectSettings/ProjectVersion.txt`에서 읽는다. 사용자의 실행 중인 Editor와 충돌하는 배치 작업을 시작하지 않는다. EditMode를 먼저, 최종 PlayMode를 마지막에 실행한다. 최종 `BounceReleaseFlowTests`의 결과를 `TestResults/release-final.xml`에 저장하고 `python tools/balance/build_level_catalog.py --accept-run`으로 최신 증거를 반영한다. 카탈로그에서 변경 레벨의 형태와 정보도 확인한다.

검증 후 한글 제목·설명으로 커밋하고 해당 원격 브랜치에 푸시한다. 완료 보고에는 범위, 핵심 질문, 검증 결과와 미검증 체감 요소, 문서/카탈로그, 커밋을 간결히 남긴다.
